# 按内容选版式

以下是布局选择，不是固定页数模板。同一类可有左右镜像、列宽和密度变化。制作前给每页写一句“这页要让观众记住什么”，再选结构；不要先套卡片再填字。

| 布局ID | 适合表达 | 结构与实现 | 常见问题 |
|---|---|---|---|
| `hero-split` | 产品概述、开场 | 一侧大标题，另一侧大主体；少量功能标签 | 主体太小、封面放满正文 |
| `editorial-split` | 理念、设计定位 | 衬线或有气质的短标题＋分栏正文＋图像 | 字体漂亮但正文太细或太小 |
| `full-bleed` | 场景、情绪、章节转折 | 环境大图出血，文字放安全留白区 | 文字压脸/产品，靠厚遮罩补救 |
| `comparison` | 两种方案、前后变化 | 两边沿相同维度对齐，突出真实差异 | 两列讲不同问题，无法比较 |
| `timeline` | 迭代、使用过程、里程碑 | 原生线、节点、简短阶段；必要时蛇形 | 箭头过长、节点解释超载 |
| `swimlane` | 多角色协作、系统交互 | 角色/层分行，动作按顺序连接 | 线交叉、层与时间轴混淆 |
| `layered-architecture` | 系统组成、技术分层 | 清楚的层级、输入输出和少量接口关系 | 把技术名词堆成Logo墙 |
| `annotated-product` | 机构、接口、产品特点 | 一张大主体＋少量局部引线与原生标注 | 标注挡住结构、引线指错位置 |
| `bento` | 主次明确的多项成果 | 大单元承载主图，小单元放细节或说明 | 所有单元同权重，变成九宫格 |
| `evidence-caption` | 实拍、测试、原型成果 | 一张主证据＋局部细节＋紧邻的事实说明 | 只放美图，没有说明来源与完成状态 |
| `matrix` | 多方案、多维度比较 | 原生表格或对齐网格；明确行列含义 | 空表过大，用装饰替代结论 |
| `data-focus` | 有来源的指标或趋势 | 少量图表＋直接结论＋来源与口径 | 无数据却捏造百分比、饼图和趋势 |
| `statement-chapter` | 章节、关键结论 | 大编号或一句短判断，大留白，可少量点缀 | 章节页仍塞入三段正文 |
| `roadmap` | 后续方向、优先级 | 阶段、目标与完成状态并列或沿路径展开 | 把后续计划写成已实现功能 |

## 组合节奏示例

8页产品稿可从“开场大图 → 需求与定位 → 对比 → 流程 → 架构 → 主体标注 → 关键结论 → 后续路线”中选择。它展示多种叙述方式，不意味着每份8页稿都必须有这8种页型。

有参考图时先分析其节奏：忠实复刻保留；用户要求丰富排版时，优先改那些内容不同却套了同一种布局的页面。正文同一主题连续讲两页时可用镜像、主辅图比例或密度变化，不必另造一种风格。

## 选布局的快速判断

- 一个强主体或一个重要判断：给它更大面积，不必分成三张卡片。
- 多个对象需要比：先写共同维度，再选并置或矩阵。
- 动作有先后：路径/时间线；跨角色交互：泳道。
- 需要说明系统如何组成：架构；需要说明实物在哪里：主体与引线。
- 需要证明做到了什么：证据图和紧邻说明；没有实拍时明确概念或待验证。
- 多个同等要点：列表、分栏、少量卡片皆可，取决于字数与配图。

版式与表达可按需要自定义ID。`scripts/review_design_plan.py`识别常见重复倾向，但不会禁止自定义结构，也不会自动改动用户选定的模板。
