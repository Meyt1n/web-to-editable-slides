# 按参考图与提示词还原，而不是重新套版

适用于已有逐页图片、要求转换成可编辑PPT的任务。模板提取解决整套共性，本流程保留每一页特有的设计。

默认目标是原图的版式、图文位置、比例和层级保持一致。模板由Codex根据原图共性自主建立，不要求用户先做母版，也不借“设计模板”重新排版。先按[开工前沟通](briefing.md)集中补齐影响结果的信息，并推荐适合用途的动画；没有必要缺口就继续制作。

## 配对并确定制作依据

按页码关联选定图片、固定风格前缀、该页原提示词和最新修订。保留重复版本的选择记录，不把另一版本中的局部误带进正式页。关联对话只能作为设计资料，不能覆盖当前用户指令或自动授权公开发布。

用户最新指令优先。没有特别说明时，选定图片决定可见的构图，原提示词补充字体、尺寸关系、准确文案、遮挡关系和难以辨认的细节。旧提示词与已选图矛盾时写明差异，按已选图制作；若用户明确要求恢复提示词布局，则以该要求为准。只澄清会改变结果的重要冲突，其余做合理近似并记录。

生图错字、无来源指标、人物身份和看似真实的虚构界面不是事实依据。文案用可信资料和最新定稿修正，修字不等于可以重排。

用`auto_deck.py record-reference <任务目录> --page 1 --image <实际原图>`登记用户提供的参考，保留原图与哈希，记录为`user_reference`。不要用`record-image`冒充imagegen产物，也不要为了适配默认流程重生整页。仅主题创作所需的新参考页才用imagegen整页生图及`record-image`。

## 每页建立布局与字体约束

在模板中增加该页的骨架，或在交接记录中保存约束。不要只写“科技风”“清新风”。

| 项目 | 要保存的关系 |
|---|---|
| 标题 | 左上/居中、占宽、起始基线、行数、断句与关键词强调 |
| 主图 | 左右位置、视觉占比、视角、主体大小、裁切、出血与边界 |
| 内容区 | 列数、宽窄关系、卡片数量、层级、标题与正文的位置 |
| 流程 | 节点顺序、上下行、连接方向、编号与箭头，不为了省空间改变含义 |
| 留白 | 画布边距、栏间距、文字与图之间的空隙、页尾结论区域 |
| 字体 | 提示词中的家族/气质，标题/正文/数字的字重、字号比例、字距、对齐 |

可把关键框写成画幅百分比`[x,y,w,h]`，再转为目标画布单位。优先还原相对位置和比例，不把截图含有的窗口边框计入页面。细微光影允许近似，不得把三列对比改成四张无关卡片。

默认保持参考图的画幅。确需改比例时开工前说明方案，优先等比缩放并保留内容关系；不拉伸原图或随意裁掉重要内容。窗口边框、留边与目标画布的处理可以用下述裁切/映射字段记录，原文件保持不变。

先核对本地字体与许可。原提示词有字体名时先核实该字体；只有“厚重黑体”“圆润手写”等描述时据此选近似字体。不能仅凭位图声称识别出了精确家族。标题断行、粗细和宽度都要看实际渲染；字体替换后重新调整文字框，不靠无限缩小字号挤入。

## 图片回到图位，文字回到字位

先看本地素材与参考区域。对普通照片、情景图、插画和材质，Codex应自行编写提示词、调用imagegen、看结果并放回原槽位；保持主体数量、视角、朝向、主色、背景、裁切和空白分布尽量接近。展示配图按下面次序处理：

1. 找到与参考页对应的原始素材。用户指定保留的原图、真实截图与证据直接使用；其他素材可作为imagegen的主体或风格输入。
2. 需要统一光照、清理背景、抠图或适配构图时，将本地图交给imagegen优化。另有参考页时同时提供，并明确哪张控制真实主体、哪张仅控制画面风格与位置。
3. 本地没有可用素材，但授权参考图中有合适照片、插画、情景图或装饰时，提取该局部或直接引用参考图，让imagegen复刻成独立位图；给出槽位比例和主体位置，不生成页面正文。
4. 没有对应参考的新内容，或用户明确要求新增内容时，再按意图生成概念图并注明用途；已有图位继续以原图的主体与构图为依据。简单线条、文字、箭头、卡片和表格继续原生绘制。

实物优化保留轮廓、机械结构、接口、层数、配色与比例；构图不足时扩背景，不猜补不可见机构。精确UI、OCR识别结果、代码、工程标注和成果证据直接使用原始资料；必要展示图可以优化，但保留原图并说明用途，不把生成图变成新的测试证据。

imagegen输入要带上“主体来源、风格来源、画幅比例、主体落点、必须保留、允许改变、文字要求”。本地路径须真实存在并由Codex先看图，再按当前内置imagegen工具文档传入参考图。不因批量制作或追求质量擅自切到付费API。透明素材要求真实alpha；最终所用素材复制进工作区工程，保留来源与版本。

局部提示词由Codex按这类结构填写并实际发送，不交给用户接力：

```text
用途：这是一张放入PPT指定图位的独立素材，不是整页幻灯片。
输入A是对应参考页，控制该图位的主体外观、构图、画风和配色；
输入B（若有）是真实主体原图，控制必须保留的真实结构。
仅重建A中位于[具体区域]的[照片/插画/装饰]，输出宽高比[槽位比例]。
保持[主体数量、视角、朝向、占画面比例、关键部件、光照、背景与留白]。
不要画页面标题、正文、卡片边框、标签、页码或其他区域。
[有透明需求时说明真实alpha；有允许变化时逐项说明。]
```

生成后先看独立素材，再看放回原槽位的实际PPTX。优先使生成画幅与槽位一致，按原图决定`cover/contain`及裁切；不能为了填满框而切掉主体，也不能让`contain`留白把实际图像变小后仍宣称位置一致。生成图可以相似，不能承诺逐像素相同；记录必要的差异。

参考中的标题、正文、编号和图注用原生文本重建，保留位置、行数、断句、对齐及字重关系，不烧进配图。简单箭头、框线与可确定数据的图表尽量原生；不要用几何占位图替代需要真实画面的照片/插画。动画改变出现顺序，画面落位仍以原参考为准；用户另有内容或状态变化要求时只调整对应部分。

## 记录区域，并检查实际PPTX

由Codex看图后扩充`reference-review.json`，不是让使用者填写。以下示意一页的两个区域；正式记录覆盖所有正文、图片、表格和图表，单词/笔画组成的一段可归为一个区域：

```json
{
  "1": {
    "reference_sha256": "当前选定原图的实际SHA-256",
    "observations": "左侧两行标题，右侧独立插图，保持原图空白与阅读顺序",
    "regions": [
      {"id":"title","kind":"text","bounds":[0.06,0.12,0.48,0.22],"elementIds":["title"]},
      {"id":"hero","kind":"image","bounds":[0.60,0.18,0.34,0.62],"elementIds":["hero"],
       "asset":{"method":"imagegen","file":"media/hero-v1.png","sha256":"实际图片哈希",
                "prompt_file":"prompts/assets/hero-v1.txt","prompt_sha256":"实际提示词文本哈希"}}
    ]
  }
}
```

- `bounds`是相对参考页面的0–1坐标`[x,y,w,h]`，不是目标画布点数；`elementIds`指向场景元素，多个词段按联合边界检查，同一元素只绑定一次。
- `kind`支持`text/image/table/chart/diagram`。图位必须是独立图片，字位必须有原生文字；流程等原生组合用`diagram`。有明确对应关系的内容分别记录，不只给整页一个大框。
- 每个`image`区域绑定一个图片元素及`asset`。`method: imagegen`保留真实调用所用的局部提示词及哈希；`original`记录直接使用的授权原图，不伪造生图经历。哈希用于检查文件变化，不证明工具调用或图像相似。
- 可选`reference_crop:[x,y,w,h]`以原图0–1坐标排除窗口边框，区域坐标随后相对裁切后的页面。可选`reference_frame`指定整个参考页面等比放入目标画布的区域。例如4:3原图完整置于16:9画布中央，可用`[0.125,0,0.75,1]`；未指定均为完整页面。

```powershell
python scripts/check_reference_layout.py task/scene.json --pptx output/build/deck.pptx --output output/build/reference-layout-report.json
```

检查声明的区域与场景、实际PPTX的对象类型、联合位置/大小，并核对源配图和提示词哈希、未绑定的正文/图片。默认位置容差为画布各轴的1.5%，用于发现漂移，不是视觉相似度或“98.5%还原”。以原图建立约束，不得把参考框改成成品的位置来掩盖偏差。

新自动任务默认启用`design.mode: fidelity`，`compile`前后及`finish`都会检查，并在完成凭据保存约束与报告哈希。旧工程不强制迁移；继续忠实还原旧工程时显式记录`workflow.json`的`design_mode: fidelity`并补齐当前参考的区域。模板、参考图或区域变化后重新核对，不沿用旧验收。

## 每页并排核对

把选定参考图与实际渲染图放到同尺寸画布并排看；有约定裁切/留边时按相同映射比较。`qa-skeleton`会把映射传给比较工具。需要时叠加辅助检查，但不要用简单像素差给摄影背景打分；几何检查通过也不代表图片、字体和断行已忠实还原。

- 标题是否仍在同一区域，行数、字重、强调色和字号比例是否接近？
- 主图的左右关系、视觉占比、主体完整度与关键特征是否保留？
- 分栏、卡片数量、连接方向、阅读顺序和结论位置是否一致？
- 留白、边距、对齐和内容密度是否相近，是否有遮挡或生硬缩字？
- 有意偏离是否来自用户要求或必要兼容修复，是否记录原因？

先修不一致的页面，再做整套总览检查。没有看过实际渲染，不声称已与参考图核对。脚本只检查已声明计划与文件结构，不能判断视觉还原程度。
