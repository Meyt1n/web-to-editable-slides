# 从“可打开”检查到“可编辑、可阅读”

## 每页先看图

查看缩略总览确认风格、密度和章节顺序，再放大检查正文、脸部/产品遮挡、边界、裁切、换行和对齐。页面越密集，越要在真正使用的字体和目标软件中渲染。

PPTD生产时，使用所属演示文稿技能的图片导出工具先检查源工程；导出PPTX后另在PowerPoint或可用播放器中实开。不要仅凭ZIP检查通过就声称WPS、Keynote和PowerPoint完全一致。

## 检查可编辑性

```bash
python scripts/check_pptx.py path/to/deck.pptx --output output/report.json
```

脚本按演示顺序报告每页原生文字框、形状、图片和表格，并标出“有图片、无非空原生文字”的页面。这只是图片页提示：照片页可能合理，含大量文字的整页截图则需要重建。

进一步在软件中点选标题、编号、正文和流程节点。复杂插画保留为独立图片是合理的；不把背景全图上的文字计作可编辑正文。

## 字体

- 先确认字体来源和再分发许可；许可文件随素材交付。
- 可读性优先于完全相同的字形。目标机没有字体时，使用允许嵌入的字体，或选可接受的替代字体。
- PPTX里出现`ppt/fonts/*`不等于字体有效。脚本检查常见EOT与OpenType头，并把未知/混淆格式记为无法确认；损坏或HTML数据不得当作嵌入成功。
- 某些字体在本机未安装时，Office导出仍会替换字形。安装字体是对用户环境的修改，按用户范围处理；不要在通用脚本里偷偷安装。
- 示例构建器默认只声明字体，不自动安装或嵌入。可选的`embed_fonts_windows.ps1`调用本机PowerPoint保存字体；先自行安装示例OFL字体，保存后用`--require-fonts`验证。

## 切换

`--require-fade`检查每页有一个根级`p:transition/p:fade`，并位于`cSld`、可选`clrMapOvr`之后，以及`timing/extLst`之前。把`p:fade`嵌在页面内容树里，Office可能忽略。

只有用户要求、或确实适合现场展示时，才安排逐元素动画；页面淡入淡出与元素动画是两种设置。用户不需要切换时不要强加。

## 常见导出问题与窄修复

| 现象 | 处理 |
|---|---|
| 图标变成圆点/空白 | 保留SVG源，转成独立PNG再导出；核对图标许可 |
| 中文日志乱码 | 用UTF-8脚本和运行模式；不要修改系统区域设置来修单个项目 |
| 字体嵌入的是很小的文件 | 检查是否下载了错误页；重新用真实字体保存并检查二进制 |
| 本地导出找不到YAML模块 | 先检查项目Node/Python依赖；按后端文档设置依赖路径，避免改全局配置 |
| 浏览器导出弹窗卡住 | 先读错误并按后端文档重试；有本地导出路径时使用它，不循环盲点 |
| 数字或大标题越框 | 看真实字体渲染结果，扩大框或降低字号，再重新导图 |
| 页面改过但源工程是旧稿 | 以用户最新文件为准，只在新副本中改；避免旧源重建覆盖用户修改 |
