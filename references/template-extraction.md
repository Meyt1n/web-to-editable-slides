# 从提示图提取模板，再按模板设计

这里的提示图指网页版生成的PPT参考页图。模板应成为后续制作实际读取的设计依据，包括参数、组件、页型与必要素材，而不只是“参考一下风格”或一张无字背景。

## 1. 先看整套，再选代表页

先按页序查看缩略总览，辨认封面、目录、章节、正文、流程、证据等页型。通常选能代表共性的少量页面深入分析即可，不为凑数量重复选相似页。

只有一两张参考图时，提取已有信息，缺少的页型按相同网格、字体与组件派生，并写明是派生设计。已有模板或只改局部时直接读取现有模板，不重新生成全套。

同时读取固定风格前缀与逐页原提示词，把字体、字重、强调、对齐和布局要求与图片配对。已有参考页的独特结构也应保存成页型或页面约束；共性模板不能抹掉它的列数、图文比例、节点顺序与标题位置，具体见[逐页还原](reference-fidelity.md)。

## 2. 分离共性与内容

| 写入模板 | 留在具体页面 |
|---|---|
| 画幅、页边距、基线、列宽、间距 | 本页标题和正文 |
| 主色、强调色、背景色、文字色 | 书名、人物、指标和事实 |
| 标题/正文/数字/点缀的字体角色 | 一张具体产品图或实拍证据 |
| 卡片、编号、箭头、标签、标注的样式 | 数据内容、流程节点和结果 |
| 封面/正文/章节/流程等页型骨架 | 仅服务某一页的装饰或情境 |
| 图片裁切、圆角、阴影、照片与插画的处理 | 不能跨页复用的图像内容 |

字体不能从位图可靠辨认时记录观测气质、所选近似字体和原因，不声称找回了原字体。颜色和几何可以估计或辅助采样，但必须再看图确认，不能把植物绿色或背景纹理的颜色误当成标题规范。

## 3. 落成模板包

建议最小结构：

```text
template/
  template.json        模板ID、版本、设计参数、组件、布局与来源
  TEMPLATE.md          人可读规范、观测依据与近似处理
  references/          有授权的代表图，仅作设计依据
  media/
    background.png     可选的无字母版
    fonts/             可再分发的字体与许可；或明确系统字体要求
```

项目可使用其他等价结构。无框编辑风不需要为了格式强加卡片；无位图的模板也不需要调用imagegen。

有图像需求时，给imagegen代表图与明确约束，生成同风格的无字背景、必要装饰或独立主体；标题、正文、编号和简单结构仍在PPT里原生构建。避免把带字参考页直接铺成模板背景。

本仓库的`template_pack.py prepare`只把模型已经提取的观测与选定素材整理成模板包，不自动识别字体、推理布局或调用imagegen。

## 4. 先做一页，验证模板

从模板选择一个能代表主要结构的页型，填入真实内容，导出预览，对照来源核对：字体气质、配色、图文主次、列宽、边距、背景留白、组件与阅读密度。

检查后再批量制作。用户已经选定风格时自主完成这个核对步骤；不要因“模板确认”额外设置审批。如果参考图明显混用了冲突设计，再提出具体差异让用户选择。

自动生成`template.json`只说明规范已整理，不等于视觉检查通过。用`status: prepared`记录脚本结果，实际看图检查另记方法与结论，不让脚本冒充人工或模型的视觉判断。

## 5. 后续页面从模板派生

- 页面设计计划绑定同一个模板ID与版本，每页选择模板中的页型。
- 先读取对应布局的内容槽位和组件，再排文字与图片；内容长了先调整措辞和结构，不无限缩小字号。
- 字体、配色、网格、标签与图片处理保持稳定；有对应参考页时沿用其骨架，左右镜像、比例或密度变化只用于无对应参考的新页或用户允许的优化。
- 需要新页型时，按现有规则增加一个模板变体；必须偏离时写明`template_override.reason`，必要时提升模板版本。
- 对页面持续核对模板，而不只在最后看“每页都挺漂亮”。

一个模板可以包含多种页型，不要求所有页面套同一张底图或同一种卡片；关键是变化有共同的字体、网格、色彩与组件来源。

## 6. 脚本与检查

```bash
python scripts/template_pack.py prepare examples/template-extraction/observations.json --source-dir . --output-dir output/template
python scripts/template_pack.py check output/template/template.json
python scripts/build_demo.py --template output/template/template.json --output-dir output/from-template
python scripts/review_design_plan.py output/from-template/design-plan.json --require-template
```

模板包使用相对路径，并把所需背景、字体、许可和代表图一起保留。公开打包只使用有发布授权的素材；本仓库例子仍是全新虚构的植物主题。

设计计划格式见[模板绑定](design-plan.md)。检查只验证已声明的约束，无法自动证明最终PPT的真实字体、颜色、间距或视觉效果都符合模板；仍须结构检查与逐页导图。
